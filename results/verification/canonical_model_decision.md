## 2. Mathematical Comparison & Implementation Differences

The table below summarizes the exact mathematical mechanics of both implementations:

| Pipeline Dimension | MATLAB (`TWENTY_personalized_classifier.m`) | Python (`train_loso_ml_benchmark.py`) | Mathematical Impact |
| :--- | :--- | :--- | :--- |
| **Feature Units** | Milliseconds (`SDNN*1000`, `RMSSD*1000`, `MeanRR*1000`, `RR_IQR*1000`) | Seconds (raw values from CSV) | Changes raw feature magnitudes by $10^3$; affects gradient magnitudes in unstandardized models. |
| **Baseline Normalization** | $\Delta x = (x - \mu_{\text{base}}) / \max(\|\mu_{\text{base}}\|, 10^{-6})$ | $\Delta x = (x - \mu_{\text{base}}) / \max(\|\mu_{\text{base}}\|, 10^{-6})$ | **Identical** relative shift formula and zero-leakage protocol. |
| **Z-Score Standardization** | **None** (prepends constant bias vector $[\mathbf{1}, X]$) | `StandardScaler()` fitted on $X_{\text{train}}$ fold, applied to $X_{\text{train}}$ & $X_{\text{test}}$ | Python features have zero mean and unit variance; MATLAB features retain relative ratio scaling. |
| **Regularization** | **None** ($C = \infty$, unregularized empirical loss) | **L2 Ridge Penalty** ($C = 1.0$, $\|\mathbf{w}\|_2^2$ penalty) | Python shrinks large coefficients, reducing variance and boundary instability. |
| **Optimization Solver** | Custom gradient descent ($\alpha = 0.05$, 2500 iterations, clamp $[-50, 50]$) | Scikit-learn Liblinear (Coordinate Descent, tol $= 10^{-4}$) | Different convergence trajectories and numerical stopping criteria. |
| **Model Scope** | Single model (Logistic Regression only) | 6 Benchmark Models (LR, SVM, RF, ET, HGB, MLP) | Python provides multi-model comparative leaderboard. |
| **Decision Cutoff** | Code uses $\tau = 0.50$; reporting uses $\tau = 0.35$ | Code uses $\tau = 0.50$; reporting evaluates both | Primary natural boundary is $\tau = 0.50$; exploratory tuned point is $\tau = 0.35$. |

## 3. Detailed Investigation Questions

### Question 1: Which implementation should be the canonical production/research model?
**Decision: Python is the documented canonical machine-learning source of truth:**
- [`python/train_loso_ml_benchmark.py`](file:///C:/Users/YASH/Desktop/projects/RESEARCH%20PROJECTS/ECG_STRESS_DETECTION/python/train_loso_ml_benchmark.py)
- [`results/ML_Model_Benchmark_LOSO.csv`](file:///C:/Users/YASH/Desktop/projects/RESEARCH%20PROJECTS/ECG_STRESS_DETECTION/results/ML_Model_Benchmark_LOSO.csv)
- [`results/ML_Predictions_LOSO.csv`](file:///C:/Users/YASH/Desktop/projects/RESEARCH%20PROJECTS/ECG_STRESS_DETECTION/results/ML_Predictions_LOSO.csv)

**MATLAB Classifier Status:**
> “Secondary/historical classifier implementation using custom unregularized gradient descent. Its τ=0.35 metrics differ slightly from the Python implementation because the optimization and regularization methods differ.”

- **Reasoning:**
  1. **Standardized Solver:** Employs industry-standard, auditable, well-tested scikit-learn primitives (`LogisticRegression(C=1.0, solver="liblinear")`) with L2 regularization, avoiding ad-hoc unregularized gradient descent loops.
  2. **Multi-Model Benchmark Integration:** Python generates the complete 6-model cross-validation benchmark and feature permutation importance tables (`ML_Model_Benchmark_LOSO.csv`, `ML_Feature_Importance_Permutation.csv`).
  3. **Direct Ecosystem Interoperability:** The Python pipeline connects directly with the live telemetry receiver (`stm32_telemetry_receiver.py`), the Streamlit application (`demo/app.py`), and downstream deployment scripts without requiring a proprietary MATLAB runtime.

### Question 2: What changes would be required for MATLAB and Python to be mathematically equivalent?
To make MATLAB produce bit-exact equivalent probabilities and decisions to Python:
1. **Features:** Remove the `* 1000` multipliers in `TWENTY_personalized_classifier.m` (lines 33, 34, 36, 38) so that both pipelines consume identical units directly from `WESAD_HRV_features_expanded.csv`.
2. **Scaling:** Implement training-fold z-score standardization in MATLAB:
   ```matlab
   mu_train = mean(X_train_personalized, 1);
   sigma_train = std(X_train_personalized, 0, 1);
   sigma_train(sigma_train < 1e-6) = 1e-6;
   X_train_scaled = (X_train_personalized - mu_train) ./ sigma_train;
   X_test_scaled  = (X_test_personalized - mu_train) ./ sigma_train;
   ```
3. **Regularization & Optimizer:** Replace the custom gradient descent loop (lines 110–117) with MATLAB's native L2-regularized logistic regression solver (`fitclinear`):
   ```matlab
   model = fitclinear(X_train_scaled, y_train, 'Learner', 'logistic', ...
                      'Regularization', 'ridge', 'Lambda', 1.0 / size(X_train_scaled, 1), ...
                      'Solver', 'sgd');
   ```
4. **Thresholding:** Standardize both scripts to evaluate and report both $\tau = 0.50$ (pre-specified primary) and $\tau = 0.35$ (exploratory swept cutoff).

### Question 3: Does the live dashboard use the same model as the published primary result?
**Verified Fact: NO.**
The live dashboard is documented separately as:
> “Pooled deployment inference engine with threshold τ=0.35, streaming safety floors, feature clipping, and optional subject-specific baseline calibration. It is not the same as the 15-fold LOSO evaluation model.”

- The **published research result** represents out-of-fold predictions from a 15-fold cross-validation scheme where 15 separate models are trained on $N-1$ subjects without heuristic floors or clipping, evaluated at $\tau = 0.50$.
- The **live dashboard engine** ([`StressInferenceEngine` in `stm32_telemetry_receiver.py`](file:///C:/Users/YASH/Desktop/projects/RESEARCH%20PROJECTS/ECG_STRESS_DETECTION/python/stm32_telemetry_receiver.py#L352-L390)):
  1. Operates at **$\tau = 0.35$**, not $\tau = 0.50$.
  2. Uses a **single pooled model** fitted over all 445 windows of all 15 subjects (or static pre-trained weights in `PRETRAINED_MODEL_COEF`), rather than out-of-fold models.
  3. Imposes **hardcoded physiological minimum denominator floors** (`MeanHR >= 30.0`, `SDNN >= 5.0`, etc.) to guard against division-by-near-zero during live telemetry streaming.
  4. Imposes **heuristic feature delta clipping** (`np.clip(delta_x, -5.0, 5.0)`).
  5. Falls back to a **population resting reference** when patient-specific baseline calibration has not yet been acquired.
- **Context:** These safeguards are standard practice for streaming edge inference where the future subject's baseline is unknown, but documentation must clearly distinguish the *deployed pooled inference engine* from the *15-fold cross-validated research benchmark*.
