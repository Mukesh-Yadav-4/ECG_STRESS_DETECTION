### 3. Bidirectional Testing (Both Encryption & Decryption Directions)
- **Verified:** Yes.
- **Evidence:**
  - **Direction 1: C Encrypt $\to$ Python Decrypt**:
    1. 10,000 WESAD sample records (sequence, timestamp, raw, filtered) are written to a binary buffer.
    2. C harness executes `--encrypt-samples` using `telemetry_pack()`.
    3. Python `TelemetryParser.feed_bytes()` unpacks, validates frame sync, checks CRC-16, and decrypts the stream.
    4. Reconstructed signals match the plaintext inputs with maximum absolute error $= 0.000000000\text{ mV}$ (lossless).
  - **Direction 2: Python Encrypt $\to$ C Decrypt**:
    1. Python `build_c_packet(..., flags=0x05)` encrypts the 10,000 WESAD samples.
    2. C harness executes `--decrypt-packets` using `telemetry_verify_frame()` and `telemetry_m4d_decrypt_packet()`.
    3. Decrypted floating-point values are returned to Python and compared against original signals.
    4. Reconstructed signals match the plaintext inputs with maximum absolute error $= 0.000000000\text{ mV}$ (lossless).

### 4. CRC Validation Accuracy & Integrity
- **Verified:** Yes.
- **Evidence:**
  - **Python Receiver Verification**:
    In `stm32_telemetry_receiver.py`, `TelemetryParser._process_packet()` computes CCITT CRC-16 (poly `0x1021`, init `0xFFFF`) over bytes 2..17 (`pkt_bytes[2:18]`). A packet is dropped if CRC does not match bytes 18..19. All 10,000 packets generated by C passed CRC verification and were parsed without dropped frames (`len(pkts_c2py) == 10000`).
  - **C Receiver Verification**:
    In `c_parity_harness.c`, every incoming packet is passed to `telemetry_verify_frame(&pkt)`. The C function computes `telemetry_crc16(&pkt->version, 16)` and compares with `pkt->crc16`. All 10,000 packets generated by Python passed C CRC verification (`py2c_all_crc_valid == True`).
